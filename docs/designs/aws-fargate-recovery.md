# Fargate 재실행과 태스크 이력

[Daily Brief AWS 전환 설계](daily-brief-aws.md)의 배치 복구 기본값에 대한 제안이다.

| 설정 | 초기 제안 |
| --- | --- |
| 재실행 간격 | 이전 태스크의 종료 확인 후 첫 재실행까지 5분, 두 번째 재실행까지 15분 |
| 실행 시간 제한 | 태스크 제출부터 시도당 최대 45분. 다음 08:00 KST도 각 시도의 종료 기한으로 적용 |
| 태스크 시도 이력 | 종료 시각 기준 30일 보존. 종료를 확인하지 못한 시도 및 종료 결과 기록이 보류된 시도는 정리 대상에서 제외 |

초기값은 동일 마감의 일시 오류를 빠르게 복구하면서 연속 재실행 사이에 대기 시간을 두기 위한 제안이다. 예약 발송 전에 대표 배치의 기동 시간과 처리 시간을 측정하고 45분 안에 정상적으로 완료할 여유가 있는지 확인한다.

## 실행 및 종료 규칙

- 최초 실행을 포함해 마감당 최대 세 번을 유지한다. 재실행 예정 시각이 다음 08:00 KST에 닿거나 지나면 실행하지 않는다. 정규 실행과 매시 15분 미시작 점검이 경합해도 DSQL 조건부 쓰기로 실행권을 얻은 시도만 시작한다.
- Step Functions 상태가 시간 초과되면 태스크 중지를 요청하고 ECS `DescribeTasks`에서 실제 `STOPPED`를 확인한 후에만 재실행을 예약한다. 태스크 상태를 확인할 수 없으면 실행권을 유지하고 운영자에게 알린다. 다음 마감이 시작된 경우에는 이전 마감 복구를 중단한다. [Step Functions ECS 통합](https://docs.aws.amazon.com/step-functions/latest/dg/connect-ecs.html), [동기 작업 취소 동작](https://docs.aws.amazon.com/step-functions/latest/dg/connect-to-resource.html)
- 마감 ID, 시도 번호, 태스크 ARN, 시작·종료 시각, 종료 코드 및 분류를 시도 이력에 기록한다. 제출 응답이 유실돼 ARN이 없으면 기존 시도를 식별할 수 있는 증거를 먼저 확보한다. 30일 정책은 종료된 태스크 시도 상세 행에 적용하며 마감의 마지막 완료 지점과 SES 수락 상태는 별도로 유지한다.
- 복구 시 마지막 완료 지점부터 진행한다. SES 수락 여부가 불명확한 발송은 보류 상태를 이어받는다. 시간 초과만으로 메일 재제출을 허용하지 않는다.

## 승인 전 검증

강제 시간 초과, 중지 요청 실패, 상태 조회 실패, 제출 응답 유실, 08:00 KST 기한 및 세 번째 시도 소진을 검증한다. 각 경우에 시도 횟수와 실행권이 맞고, 이전 태스크가 실제로 종료되기 전에 같은 마감의 태스크를 새로 시작하지 않는지 확인한다. 30일 경계에서 만료된 시도만 정리되는지도 확인한다.
